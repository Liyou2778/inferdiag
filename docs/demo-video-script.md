# inferdiag 演示视频完整台本

> 用途：求职作品集 / 开源项目宣传 / 创业比赛路演
> 版本：配套 v0.2.0（采集 + R1–R14 规则 + 实时看板 + 一键检测 + 一键压测 + 报告导出）

---

## 0. 录制目标与受众

- 一句话定位（全程围绕它说）：**inferdiag 把推理引擎的指标翻译成"诊断结论"**——为什么慢、瓶颈在哪、该改什么。
- 三类受众与侧重点：
  - **技术面试官**：强调"引擎级指标→规则→证据链"、真实硬件验证、可配置阈值；
  - **比赛评委**：强调"真实用户价值 + 落地数据（真引擎实测基线）"；
  - **开源观众**：强调"零依赖、Apache-2.0、Mock 即可跑、本地/远程都能接"。

## 3. 标准版台本（3 分钟，逐镜头）

> 每一格：【画面】做什么 +【口播】念什么 +（字幕建议）。

### 镜头 1｜开场定位（0:00–0:20）
- 画面：仓库首页或看板首页定格；字幕打项目名 + 一行描述。
- 口播：
  > "部署了开源大模型的团队，手里有 Grafana 的图、有引擎日志，但缺一样东西——结论。
  > inferdiag 读 vLLM/SGLang 的指标，输出健康分、瓶颈诊断和可执行的建议。"
- 字幕："inferdiag · LLM 推理体检报告生成器"

### 镜头 2｜看板全景（0:20–0:55）
- 画面：浏览器打开 `http://127.0.0.1:8080`，鼠标依次扫过四个区域。
- 口播：
  > "这是实时看板：左上健康分；右侧诊断建议，每条都带触发它的证据值；下面是关键指标卡片；再往下是多指标曲线——每秒刷新。"
  > "注意底部的状态栏：累计请求、平均 TTFT、生成吞吐、缓存命中率、输入输出 token，都在实时跳动。"
- 字幕：健康分 / 诊断建议 / 指标 / 曲线 / 底栏，逐一点亮。

### 镜头 3｜一键检测（核心）（0:55–1:55）
- 画面：点"▶ 开始一键检测"→ 进度条推进、日志逐行滚动 → 30 秒后报告卡片弹出并自动滚动。
- 口播：
  > "真正的一键体验：点一下，它会自动采集 30 秒并实时显示进度；结束后直接生成这一次的检测报告——健康分、触发规则、证据值、关键指标，不用敲一行命令。"
  > "如果检测过程中有负载，报告里就能看到真实的 TTFT、吞吐和缓存命中率。"
- 字幕："一键检测：自动采集 → 实时进度 → 自动报告"

### 镜头 4｜一键压测 + 实时波动（1:55–2:25）
- 画面：点顶部"重"→ 曲线和底栏明显波动 → 点"停止"。
- 口播：
  > "没有现成负载？点一下'重'，它会向引擎发并发请求；看曲线和底栏立刻动起来。这种真实负载，正是诊断要捕捉的对象。"
- 字幕："内置压测：轻 / 中 / 重"

### 镜头 5｜CLI 与报告导出（2:25–2:45）
- 画面：切到终端，快速执行 `report` 和 `export -f md`，展示文件。
- 口播：
  > "同样的诊断也可以走命令行：check 出结论，report 看明细，export 导出 JSON 或 Markdown 报告。规则是 YAML 配置，阈值能按你的硬件重新标定。"
- 字幕："CLI: check / report / export"

### 镜头 6｜收尾（2:45–3:00）
- 画面：回到仓库首页，指向文档与 License。
- 口播：
  > "开源、Apache-2.0、零前端依赖，Mock 源让没有 GPU 也能跑。项目地址见简介，欢迎 star 和反馈。"
- 字幕："github.com/Liyou2778/inferdiag"

## 5. 详细版（5–6 分钟）增补镜头

在标准版镜头 2 与 3 之间插入：

- **镜头 2.5A｜Mock 病态对照（约 40s）**
  另起 `serve_mock_metrics.py --mode stress` + 独立库 → `check` 显示健康分骤降、OOM/排队/TTFT 告警 → 强调"能区分病与健康"。
- **镜头 2.5B｜阈值可配置（约 30s）**
  打开 `rules/rules_v0.yaml`，改一个阈值 → 重新 check 触发变化 → 说明"规则=配置，按硬件标定"。
- **镜头 5.5｜实测口径（约 40s）**
  展示 `docs/calibration.md`：RTX 4060 + WSL2 + vLLM 0.8.5 + Qwen3B 的实测基线（空闲 KV 0%、负载 KV≈3%、TTFT p50 40ms），说明结论来自真实数据。

## 6. 亮点话术速查卡

| 要点 | 一句话 |
|---|---|
| 定位 | 不做第 N 个监控面板，做"面板之上的诊断层" |
| 差异 | Grafana 给图，inferdiag 给结论+建议+证据 |
| 可信 | 阈值按真实硬件实测基线标定（docs/calibration.md） |
| 工程细节 | 计数器按标签求和、histogram 分位估算、子窗口空转判定 |
| 易用 | 一键检测 / 一键压测 / Mock 无 GPU 可跑 |

## 7. 常见翻车与补救

| 状况 | 补救 |
|---|---|
| 压测没触发告警 | 正常（引擎健康）。改为：加大压测档位，或用 Mock `--mode stress` 录"病态"片段 |
| 曲线太平 | 先点"重"压测再录；或开持续负载 |
| 检测报告只有"未发现明显问题" | 检测窗口内没有负载。改成：点检测后立刻点"重"/继续在 chat_local.py 提问 |
| 连接失败/空白 | 硬刷新（Ctrl+Shift+R）；确认引擎 8000、看板 8080 都在 |
| 口误 | 不 NG 整段，暂停 1 秒后重念该句，后期剪掉 |
| 露了无关窗口 | 用"窗口捕获"而不是"显示器捕获"，只录看板/终端窗口 |
