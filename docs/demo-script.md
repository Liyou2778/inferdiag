# 3 分钟产品演示脚本（录屏用）

> 目标：让面试官/评委在 3 分钟内看懂"这是什么、解决什么问题、有没有真本事"。
> 环境：vLLM 引擎(8000) + 实时看板(8080) 已在后台运行（`docs` 与 `scripts` 下均有配套）。
> 建议录屏前先完整彩排 1 遍，控制每段节奏。

---

## 第 0 段 · 开场定位（20 秒，口播或字幕）
> "部署了开源大模型的团队，现在只有 Grafana 的图和引擎日志——知道指标，但不知道结论。
> inferdiag 把引擎指标翻译成诊断结论：为什么慢、瓶颈在哪、该改什么参数。"

画面：仓库首页 / README 首屏。

## 第 1 段 · 看板全景（40 秒）
1. 打开 `http://127.0.0.1:8080`；
2. 依次指向四个区域，各一句话：
   - 健康分（当前值 + 颜色语义）；
   - 诊断建议（触发规则、证据值、建议文本）；
   - 指标卡片（KV cache / TTFT / TPOT / E2E / 到达率 / 前缀命中）；
   - 实时曲线（说明每秒刷新、多指标独立缩放）。

## 第 2 段 · 一键压测演示（60 秒，核心亮点）
1. 点看板顶部的 **"重"**（6 并发 × 28 请求 × 800 token）；
2. 把镜头对准右侧状态行与曲线：
   - 状态行从"空闲"→"压测进行中 · 成功 N/失败 M" 递增；
   - KV cache、运行中请求曲线开始波动，TTFT 出现变化；
   - 健康分随负载变化（可用"中/重"档制造一次真实告警，如 TTFT/E2E 触发 R3/R11）；
3. 点 **停止**，说明后台采集线程不受影响、看板持续工作。

## 第 3 段 · 诊断可追溯（40 秒）
1. 切到终端，展示同一时间窗口的 CLI 输出：
   ```bash
   uv run inferdiag check --db data/live.db --window 60
   ```
2. 强调"证据链"：每条建议都带触发它的实际指标值；
3. 展示阈值可配置：打开 `rules/rules_v0.yaml` 说明规则=配置（YAML），改阈值立即生效。

## 第 4 段 · 报告导出与收尾（20 秒）
```bash
uv run inferdiag export --db data/live.db -f md -o docs/sample-report
```
展示生成的 markdown 报告文件；收尾口播：

> "开源（Apache-2.0），规则与引擎无关可自定义，阈值按你的硬件重新标定即可。
> 项目地址：github.com/Liyou2778/inferdiag。"

---

## 录制小贴士
- 1080p、窗口内录（别露无关桌面）；OBS / 系统录屏均可；
- 压测用"中"或"重"档制造可见波动——本机为 RTX 4060，若波动不明显可把 `max_tokens` 调大或连续点两次；
- 若某一轮压测没触发告警，属正常（说明引擎健康）；演示"告警场景"可直接用 `scripts/serve_mock_metrics.py --mode stress` + 独立库快速录制一段。

## 一段话版本（简历/社交简介用）
> inferdiag：读 vLLM/SGLang 的 Prometheus 指标，输出健康分 + 瓶颈诊断 + 可执行建议，带实时看板与一键压测演示；规则阈值可配置、按真实负载标定，15 项自动化测试 + 10 项人工验收。
